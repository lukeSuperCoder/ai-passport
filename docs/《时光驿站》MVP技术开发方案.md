# 《时光驿站》MVP 技术开发方案

> 文档状态：技术方案 v0.1  
> 目标平台：FoloToy AI Passport / ESP32-C3 / 8 MB Flash / 无 PSRAM  
> 上位文档：《时光驿站》第一版 MVP 功能设计、《时光驿站》硬件资源分析与游戏资源预算  
> 开发基线：ESP-IDF 5.5.x，LVGL 9.x，现有 BSP 和桌面模拟器

## 1. 方案目标

本方案将已确认的 MVP 功能转换为可分期实现、可测试、可持续检查内存的嵌入式游戏架构。首先保证经营闭环和断电安全，再增加完整内容和表现。

技术成功标准：

- 同一套纯 C 游戏逻辑同时运行于 ESP32-C3 和桌面主机测试。
- 只存活当前 LVGL 页面，不使用全屏帧缓冲或整张图片解码缓冲。
- 任务以截止时间结算，不为每个岗位或生产任务创建 FreeRTOS 任务。
- 存档支持 A/B 双副本、版本迁移、CRC 校验和断电恢复。
- 最复杂页面与音频并发时最低空闲堆不低于 32 KB，最大连续 DMA 空闲块不低于 16 KB。
- App 不超过 1.70 MB 目标，只读资源包不超过 4.50 MB 目标。

## 2. 已确认约束与待验证项

### 2.1 已确认

- ESP32-C3 单核，400 KB 内部 SRAM，无 PSRAM，8 MB Flash。
- 240 × 320 RGB565 屏幕，现有 20 行单 LCD DMA 缓冲为 9,600 B。
- LVGL 内部内存池为 24 KB。
- 三键共用 ADC；回调不能阻塞，LVGL 操作需持有锁。
- ES8311 当前使用 I2S TX/RX 全双工；正式游戏不需要录音。
- MVP 不依赖联网、BLE、OTA 或外部存储。

### 2.2 待第一阶段实测

- 当前基线的 App/DRAM/IRAM 精确占用。
- 显示、按键、电池、仅 TX 音频初始化后的 free heap 和 largest block。
- 板上真实时钟的可用性、断电保持方式与首次设时交互。
- 只读资源分区的最佳读取块大小以及 Flash 读取与 LCD/I2S 并发时的表现。

以上待验证项不阻止桌面端逻辑开发，但它们是第二阶段进入内容生产前的门禁。

## 3. 总体架构

```text
按键 / 系统时间 / 电池
          ↓ 轻量事件
    app_controller（唯一交互入口）
          ↓ action
    game_reducer（纯逻辑状态转移）
       ↙       ↓        ↘
game_state   domain systems   effect queue
                         ↙      ↓       ↘
                  save_service  audio  page_router
                                           ↓
                                      当前 LVGL 页面

assets partition → asset_reader → 小块解码/绘制/音频流
game_save partition ↔ save_service ↔ game_state
```

架构采用“纯状态内核 + 副作用服务 + 短命页面”：

1. `game_reducer` 接收 action，同步修改 `game_state` 并生成 effect。
2. effect 由服务层执行，如写存档、播音效、打开页面。
3. UI 不直接改存档或经济数据，只派发 action 并从状态生成视图。
4. 纯逻辑不依赖 ESP-IDF、FreeRTOS 或 LVGL，使离线结算、经济和存档迁移可在主机端确定性测试。

## 5. 运行时模型

### 5.1 任务与并发

目标只使用少量长存任务：

| 执行上下文 | 职责 | 规则 |
| --- | --- | --- |
| LVGL/GUI | 页面对象、动画、视图刷新 | 不做 Flash 写入和阻塞音频 |
| button component | 转换为小型输入事件 | 不跑游戏结算，不持久化 |
| app worker | 离线补算、存档序列化、资源预读 | 单队列，避免状态并发修改 |
| audio worker | 小块解码并阻塞写 I2S | 只读播放命令和资源 |

游戏内的岗位、农作物、旅行和事件是数据记录，不是 FreeRTOS 任务或软定时器。

### 5.2 状态所有权

- `game_state` 只能在 app worker 或持有应用状态锁的 reducer 上下文中修改。
- UI 使用快照或 view model，不长期持有游戏对象指针。
- effect 带单调序号，存档记录最后已提交序号，用于避免重复领取。

### 5.3 启动顺序和失败降级

```text
BSP 最小初始化
  → 显示 + LVGL（失败则终止并记录）
  → 按键（失败则显示不可操作故障页）
  → 读取分区与资源包头
  → 读取 A/B 存档、选择最新有效副本
  → 时间信任检查和离线补算
  → 驿站主页
  → 延后初始化电池和音频
```

电池失败显示未知图标；音频失败进入静音模式；二者均不阻止游戏。资源包不匹配 App 版本时进入诊断页，不冒险继续读取。

## 6. 核心数据设计

### 6.1 基本规则

- 使用固定宽度整数和资源 ID，存档中不保存指针、正文、图片或可变长字符串。
- 数量有 MVP 上限的对象使用定长数组，如 4 宠物、6 地块、2 厨房槽、3 待处理重要事件。
- 内容定义与可变运行状态分离；存档仅保存 ID 及进度。
- 金币、经验、时间和计数器全部使用有界整数并做溢出保护。

### 6.2 游戏状态分区

`game_state` 逻辑上分为：

- header：存档版本、提交序号、随机种子、内容版本。
- time：最后可信时间、季节起点、游戏日、当日天气。
- progression：引导步骤、主线任务、建筑等级、解锁位图。
- pets/jobs：宠物数值、关系、岗位和截止时间。
- economy：金币、口碑、定长物品计数、上架格。
- world：农田、厨房、森林、旅行和日历状态。
- events：解锁/完成位图、冷却、最多 3 个重要事件。
- pending：待领取的确定性收益和最近 10 条日志。
- settings：音量、亮度、息屏、12/24 小时制、语言。

第一个可运行骨架中要加入 `static_assert` 或构建时尺寸检查，使核心状态结构目标不超过 12 KB。

## 7. 时间与离线结算

### 7.1 时钟分层

- monotonic clock：本次启动内动画、按键、音频和存档合并写延迟。
- wall clock：真实日历、时段、跨日和离线任务。
- trusted time：对 wall clock 的包装，检测向后跳变、超过 7 天前跳和未设置状态。

### 7.2 确定性补算

输入为存档快照、最后可信时间、当前时间和内容表；输出为新状态和一份 pending report。

算法按“下一个截止时间”跳跃，不按分钟模拟：

1. 校验时间并将有效区间截断到 7 天。
2. 按时间排序跨日、生产、岗位、旅行等候选边界。
3. 相同时刻按固定优先级处理，与功能文档的 8 步顺序一致。
4. 随机结果由存档随机种子 + 任务 ID + 结算次数派生，保证重放结果一致。
5. 普通收益进入 pending；岗位经验、体力和心情直接写入状态。
6. 先原子保存补算后状态，再允许 UI 进入领取流程。

必测边界：0 秒、10 分钟、跨日、第 7/14 日、6 天 23:59、7 天、超过 7 天、时间倒退、存档重放、同时到期、库存溢出。

## 8. 存档与持久化

### 8.1 分区

使用硬件资源文档已建议的无 OTA 分区：2 MB App、5.81 MB assets、128 KB game_save。正式开发前将 `partitions.csv` 和对应 `sdkconfig.defaults` 选项纳入版本库。

### 8.2 A/B 格式

每个 slot 包含：

```text
magic | format_version | content_version | sequence
payload_length | payload_crc32 | header_crc32 | commit_marker
payload
```

写入顺序：写非活动 slot 的 header/payload → 验证回读 CRC → 最后写 commit marker。启动时选择 CRC 有效且 sequence 最新的 slot。

保存触发：

- 领取收益、消耗物品、开始/取消任务、事件选择：必须持久化后才显示成功。
- 导航、临时选中、动画：不写存档。
- 亮度、音量等设置：合并延迟 1～2 秒写入。
- 离线补算：完成后立即写入，之后才展示报告。

存档序列化不直接 dump C struct，应使用显式字段编码，避免对齐、编译器和字段重排导致不可迁移。

## 9. 资源系统

### 9.1 发布格式

首版优先使用简单只读 pack，不引入通用文件系统。包头包含版本、总长度、索引数量和 CRC；索引项包含 resource ID、类型、格式、偏移、长度和校验值。

资源类型：

- 场景：分层索引色/块压缩，小块解压到 5～12 KB 共享 scratch buffer。
- 精灵和图标：图集 + 透明索引色，只读索引定位。
- 文本：UTF-8 文本块 + 偏移索引，UI 仅缓存当前 1～2 页。
- 字体：从定稿文本自动提取字形，构建时缺字即失败。
- 音频：16 kHz 单声道 IMA ADPCM 流或轻量合成数据。

### 9.2 构建门禁

资源构建必须输出分类体积报告，并在以下情况失败：

- 总包超过 4.50 MB 日常目标；发布例外需显式批准，且绝不可超分区实际容量。
- 存在未被内容表引用的孤儿资源或重复 ID。
- 中英文本使用字形不在子集中。
- 大图不支持分块解码，或单块解码需求超过 12 KB。

## 10. UI 和三键交互

### 10.1 导航模型

- 顶层为驿站、安排、农田、旅行、背包五个 tab。
- 底部 tab 在主页默认隐藏；方向键唤出，超时再隐藏。
- 页面栈深度最大为 3；长按 `OK` 返回上一层，根页长按回驿站。
- 列表统一使用 `UP/DOWN` 选择和 `OK` 确认；需要二次确认的破坏性操作必须使用独立确认页。
- 重复设置优先批量操作，不依赖长按方向键完成核心流程。

### 10.2 页面生命周期

每个页面仅实现 `create/update/destroy/handle_key`。路由切换时先停止定时器和异步回调，再销毁屏幕对象。页面不缓存离开后的 LVGL 树。

每页增量 RAM 目标不超过 24 KB；超过 20 KB 即需记录原因和实测数据。复杂列表使用固定数量行容器复用，不为全部内容创建对象。

### 10.3 主场景渲染

驿站场景使用基层 + 建设层 + 时段色板/光照层 + 天气层 + 精灵层，禁止生成 64 张全屏组合背景。动画只刷新变化区域，低电量时降低精灵和环境帧率。

## 11. 音频方案

第一版技术选择为“I2S TX-only + 16 kHz mono + 分块播放”。

- 在 BSP 中增加可复用的仅播放初始化路径，不破坏现有硬件 demo 对全双工的需求。
- 正式 App 不编译录音 demo，不分配 96 KB 录音缓冲。
- 音频 worker 复用 2～4 KB 输入块和 4～8 KB PCM 环形缓冲；初步总目标不超过 12 KB。
- 同一时刻只播放一路背景和一个短音效；若混音增加峰值或卡顿，MVP 退化为音效打断/压低背景音。
- 第一轮只制作日间、夜间两组循环音乐，保留四时段资源 ID。

## 12. RAM 预算与复用策略

| 区域 | 目标 | 生命周期 |
| --- | ---: | --- |
| LVGL 池 | 24 KB | 常驻 |
| LCD DMA | 9.6 KB | 常驻 |
| I2S TX DMA | 约 5.6 KB + 描述符 | 音频初始化后 |
| 核心状态 | 8～12 KB | 常驻 |
| 当前页对象 | 8～20 KB | 页面存活期 |
| 共享 scratch | 8～12 KB | 图片解码/存档二选一 |
| 音频流 | 6～12 KB | 播放期 |
| worker 栈与队列 | 8～12 KB | 常驻，依高水位下调 |
| 系统安全余量 | ≥ 32 KB | 任何运行状态 |

图片解压与存档序列化共享同一 scratch buffer，通过 app worker 串行化；音频需要独立小缓冲以避免断音。禁止普通路径中连续分配超过 16 KB，任何超过 12 KB 的新单次分配都应审查。

## 13. 测试与可观测性

### 13.1 主机纯逻辑测试

至少覆盖：

- 岗位评分边界与收益映射。
- 任务分配互斥、取消和低体力自动离岗。
- 农田生长、天气、无人照料和下一轮计划。
- 厨房材料消耗、品质、研究进度。
- 离线 7 天上限、时间异常、随机重放、重复结算防护。
- 待领取与库存溢出的事务性。
- 存档序列化往返、CRC 损坏、A/B 回退和版本迁移。
- 10 个主线任务和 65 个事件的可达性、唯一性和引用有效性。

### 13.2 模拟器测试

扩展现有 SDL/LVGL 模拟器，支持注入指定时间、时间跳转、电量、存档损坏和音频失败。用模拟器验证三键主流程、页面层级、文本溢出和重复进出页面的内存错误。

### 13.3 设备诊断

开发构建保留诊断页/串口命令：

- 显示 free heap、minimum free heap、largest 8-bit block、free/largest DMA block。
- 显示当前页、游戏状态大小、存档序号、资源包版本。
- 可调整游戏时间、天气、金币和任务截止时间，但仅在开发构建编译。
- 记录每次页面 create/destroy 前后堆差值和 worker 栈高水位。

## 14. 开发里程碑

### M0：基线和内存建档（1～2 天）

- 保留现有 demo，记录 `idf.py size*` 和分区表基线。
- 增加 heap/DMA 遥测点，真机采集外设初始前后数据。
- 验证 I2S TX-only，记录回收的 RAM 和音频稳定性。
- 引入自定义分区表并验证 8 MB Flash 布局。

**退出门禁**：有构建数据和真机内存基线；分区可正确擦写；TX-only 不破坏播放。

### M1：可测试游戏内核（3～5 天）

- 定义 ID、`game_state`、action/reducer 和内容表骨架。
- 实现岗位评分、任务截止时间、库存和离线补算最小闭环。
- 实现主机纯 C 测试和确定性 clock/RNG。

**退出门禁**：无 LVGL 情况下可模拟“排班→前进 6 小时→生成报告→领取→重启不重复”。

### M2：存档与垂直切片（5～7 天）

- 实现 A/B 存档、CRC、内存后端和 Flash 后端。
- 用程序员占位美术完成驿站、安排、离线报告三个页面。
- 实现墨墨接待和阿麦 30 分钟森林采集。
- 端到端跑通首次点灯到欢迎回来。

**退出门禁**：桌面模拟器和真机均能完成首个离线闭环；断电注入不会重复领取。

### M3：经营闭环（2～3 周）

- 农田、厨房、接待、森林、旅行和背包五大模块。
- 4 宠物、4 岗位、4 作物、5 配方、1 旅行目的地。
- 火候小游戏和两组临时循环音乐。
- 只读资源包 v1 和字体子集流程。

**退出门禁**：核心资源循环完整；任何常用操作不超 3 层；复杂页 + 音频满足 RAM 红线。

### M4：故事和 14 日内容（2～3 周）

- 10 个主线任务、6 名重要旅客、约 65 个事件。
- 宠物关系、图鉴、建设阶段、第 7/14 日节点。
- 内容静态校验：无效 ID、不可达任务、缺字、资源超预算。

**退出门禁**：自动模拟能从新存档走到春 14 日；主线无卡死，独特奖励无重复。

### M5：美术、音频和稳定性（2 周）

- 替换占位资源，完成分层驿站、精灵、事件画面和正式音频。
- 连续 24 小时、反复进出页面、Flash/I2S/LCD 并发压力测试。
- 完成 README 真机验收清单和发布资源报告。

**退出门禁**：App/assets/RAM 全部达标，无持续泄漏、重启循环、分配失败或存档不一致。

## 15. 首个开发迭代的任务拆分

建议立即进入 M0，不先制作大量页面或正式美术。第一迭代交付：

1. 新增并验证 `partitions.csv`。
2. 新增通用 heap/DMA 遥测 API 和启动阶段日志。
3. 为正式 App 增加 ES8311/I2S TX-only 能力，保留 demo 全双工路径。
4. 建立 `game_types` / `game_state` / `game_reducer` 最小骨架和主机测试命令。
5. 实现一个仅包含墨墨、接待岗位、金币和 6 小时离线报告的确定性用例。
6. 输出基线报告：Build/size、初始化各节点 heap、TX-only 对比、未执行的真机项。

## 16. 需要在 M0 内锁定的产品/硬件决策

下列问题不影响启动架构工作，但需在 M0 结束前得到实测或产品结论：

- 设备无网络时，wall clock 如何设置、断电后能否保持；若不能，首启和每次掉电后的三键设时流程必须纳入 MVP。
- 中文是否为首发必选语言；如是，需明确修改当前“UI 文本保持英文”的工程约定。
- 低电量阈值、息屏时间和夜间亮度是产品策略还是可调设置。
- 首版音乐使用 IMA ADPCM 还是模块合成；默认优先 ADPCM，因为实现风险更低。
